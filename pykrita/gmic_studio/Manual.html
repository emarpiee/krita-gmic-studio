G'MIC Studio

A docker for running G'MIC filters on the active paint layer. It runs entirely offline. The only network access is the optional Update filter list button in Settings.

Setup

  1. Enable the plugin in Settings > Configure Krita > Python Plugin Manager and restart Krita.
  2. Show the docker: Settings > Dockers > G'MIC Studio. Its own settings are behind the gear next to the search box; the line about gmic only appears when gmic is missing.
  3. Filter list. The docker shows the same filters as Krita's G'MIC-Qt. It reads the list G'MIC-Qt caches in its config folder (gmic_qt_filters.dat), so open Filters > G'MIC-Qt once and let it load. Without that cache you get a small built-in set; Settings > Update filter list downloads the full list (only when you click it).
  4. The gmic program. Krita's own G'MIC-Qt cannot be driven by other plugins, so G'MIC Studio runs the standalone gmic command-line program. Open Settings > Get gmic...: on Windows it downloads the official build from gmic.eu into the plugin's private folder; on Linux and macOS it shows the package-manager command for your system (for example sudo dnf install --setopt=install_weak_deps=False gmic). You can also use Browse or Import from archive. The Flatpak build of Krita cannot see programs installed on the host, so use Import from archive there. Keep gmic reasonably up to date: filters newer than your gmic report "unknown command".

Using it

  • Search or browse the filter list. Star a filter to pin it under Favorites. The Recent button next to the search box opens a menu of the filters you used recently; choosing one opens it in its category, and Clear recent filters at the bottom empties the list. In the search box, Esc clears the text and a second Esc leaves the box, Enter moves to the results so the arrow keys step through them, and clicking empty space also leaves it. The list remembers which categories you opened and where you scrolled, so applying a filter or pressing undo/redo never closes them.
  • Change parameters. With Live preview on, the preview re-renders after a short pause, and old renders are cancelled when you keep tweaking. It also refreshes by itself when you switch layers, change the selection or paint (Krita does not announce these, so the docker checks about once a second; turn it off in Settings if you prefer Refresh). A busy bar shows while it renders; a slow filter that keeps restarting while you drag a slider is the usual reason a preview seems stuck. Hold Compare to see the original. Point parameters show as handles on the preview; dragging one updates the preview live (on a smaller, faster image) and renders full quality when you let go. Button parameters (such as Reset 3D Position) run the filter once with the button pressed; parameters G'MIC marks as hidden stay out of sight and ones it marks as unavailable are grayed out. Some filters change the picture's size (3D views with their own Width and Height, borders). The preview then shows the whole result with a dashed frame marking the part that lies over your canvas; ⋯ → Keep the original size cuts the result to that frame, in the preview and in Apply. The ⋯ menu's Preview mode offers G'MIC-Qt's views: forward/backward horizontal and vertical splits and checkered (with a draggable divider) and the duplicate layouts. The ↻ button renders the preview again at full size, Fit and 100% change the zoom (the zoom level is shown inside the preview), and the ⋯ menu holds the forced-transparency, auto-refresh and new-seed options. The status line says what the preview shows:
    • whole image: images up to about 3 megapixels are previewed by running exactly the job Apply would run, so the preview matches the result;
    • scaled image / 1:1 crop: bigger images follow the filter's own preview setting (G'MIC-Qt's rule): a scaled-down whole image for filters made for it, otherwise a crop at actual size around the selection or the canvas centre. Such previews can differ from the final result for filters that depend on image size.
    Random filters (Blockism, Array [Random Colors], ...) use one random seed for both the preview and Apply, so the result you see is the result you get. Choose New random seed in the ⋯ menu above the preview (or in the Randomize menu) to roll a different one.
  • Zoom the preview with the mouse wheel (it zooms at the cursor), drag to pan, double-click to switch between fit and 100%, or use the Fit and 100% buttons. Transparent areas show as a checkerboard.
  • Presets in the document. Save preset... asks where to keep a preset: My library (a file, available in every document; the default), This document (stored inside the .kra file, so it travels with it and shows up whenever the file is opened), or both (tick both boxes: you get one independent copy in each). The two places are separate and are never merged behind your back. Right-click a preset to Copy it to the other place. The Presets tab lists both (document presets are marked [document]), and the box next to This filter only narrows it to one source. A document preset is saved with the file, so save the document after adding one; Krita is told the document changed.
  • Presets live in one library, listed together on the Presets tab next to Filters: every preset of every filter in one flat list, so there is nothing to browse through. The most recently used come first. Click one to load and preview it (it switches to its filter with its values), double-click to apply it, or use the Up and Down arrow keys in the list to step through it and watch the preview change. The search box searches both tabs and jumps to the one that has results. Tick Only this filter's presets to narrow the list to the current filter.
    • Save preset... stores the filter and its current values; tick the box to also remember the random seed, so a random filter reproduces the exact look. Update overwrites the loaded preset with the current values.
    • Right-click a preset, or use the ... menu, to rename, delete, export or import presets and to open the presets folder.
    • Presets are kept in one file in the plugin's config folder. Settings > Presets file moves the library file, for example into a synced folder, and export/import shares presets as a file.
  • Apply runs the filter in the background; the list next to it decides what happens with the result (Krita cannot record direct pixel edits from plugins, but it does record layers, so every mode is undoable):
    • New layer: the result goes on a copy of the layer above the original, which stays. Ctrl+Z removes the new layer.
    • New layer, hide original: the same, then the original is hidden. Ctrl+Z twice undoes both.
    • Replace original: the result takes the original's name, position and masks and the original is removed. Ctrl+Z twice brings it back.
    Stop cancels a running filter.
  • Tools > Scripts > Repeat Last G'MIC Studio Filter re-applies the last filter with the same values. Assign a shortcut under Settings > Configure Krita > Keyboard Shortcuts.
  • An active selection limits the filter, including soft (feathered) edges.
  • Transparency. Like Krita's own G'MIC, filters receive the layer with its transparency (RGBA), so filters that move or tile content keep the transparent background. A few filters only accept RGB images; in the default Automatic mode the plugin retries those on the colors alone and puts the original transparency back. Change this in Settings.
  • Force transparent background (off by default). Many filters paint an opaque fill (often black) over the transparent parts of a layer. Some of them have their own parameter for a transparent result (look for something like Result Type or a background option); use that when it exists. For the filters that do not, tick Force transparent background (in the ⋯ menu above the preview and in Settings) and one general rule clears the fill, with no special cases for particular filters:
    • The plugin looks at spots that were transparent in your layer. If the filter turned them all into (roughly) the same opaque color, that color is the filter's background. If they came out transparent, varied or translucent, nothing is done.
    • A pixel close to that color is cleared when it was empty in your layer or was changed by the filter. Pixels the filter left as they were, such as a black pupil in your artwork, stay.
    • Clearing is soft: pixels fade from transparent near the fill color to opaque further away, and the fill is taken back out of the colors, so edges stay clean without dark halos. This also covers noisy fills such as brush-stroke textures.
    • When a filter adds a border around the layer (frames), the added border counts as empty too, so a fill there is cleared, but the shapes the filter draws (like a white frame line) stay.
    Leave it off when you want the fill itself, for example a render filter on a sparsely painted layer. A completely empty layer is never touched.

If something goes wrong

Errors appear under the preview and are also written to a log file (Settings > Log file shows where, with a button to open the folder). Include its last lines when reporting a problem.

Limits

  • Paint layers in RGB(A), 8-bit or 16-bit integer. Convert other layers first.
  • Filters see the whole canvas (limited to the selection if there is one), like Krita's own G'MIC. A filter that changes the image size (frames, borders, crops) cannot replace the layer, so its result is added as a new layer, centered on the original; selection blending is skipped for such filters.
  • Filters that need the internet, a second layer, or a newer gmic than the one installed report an error instead of running.
